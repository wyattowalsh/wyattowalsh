# I13 — List METRICS_TOKEN gates (boolean only)

**Date:** 2026-08-14  
**Status:** complete

## Evidence

`generate-profile-metrics` (and probe) `metrics_auth` step:

- Reads `secrets.METRICS_TOKEN` into env.
- Sets `has_valid_metrics_token=false`, then `true` only if `GET https://api.github.com/user` returns HTTP 200.
- Echoes **only** the boolean to `$GITHUB_OUTPUT` and a notice if invalid. Never prints the token.

Boolean-gated `with:` (production):

| Plugin | Gate |
|---|---|
| `plugin_traffic` | `has_valid_metrics_token == 'true' && 'yes' \|\| 'no'` |
| `plugin_notable_repositories` | same |
| `plugin_stargazers` | same |
| `plugin_stars` / `plugin_stars_limit` | yes/16 vs no/0 |
| lowlighter `token:` | METRICS_TOKEN if valid else `github.token` |
| supplemental `GITHUB_TOKEN` | same |

`plugin_languages: yes` is **unconditional** (threshold 0% on prod). Languages still depend on a working token for a full panel, but the YAML flag is not boolean-gated.

`test_invalid_metrics_token_disables_elevated_scope_plugins` asserts the gate string on traffic / notable_repositories / stargazers / stars. Supplemental `with:` block is asserted not to contain `METRICS_TOKEN:`.

## Finding

Token handling is boolean-only. Elevated GitHub-native plugins (traffic, notable repos, stargazers, stars) stay off without a valid PAT. Secrets are not logged.

## Gap

None for this inventory. Token rotation, if needed, is out-of-band.

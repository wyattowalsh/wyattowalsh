---
title: Fetch Metrics
description: Collects live GitHub REST and GraphQL metrics — stars, commits, followers, repos — into a structured JSON file.
---

## Module

`scripts/fetch_metrics.py`

Shared HTTP helpers live in `scripts/_github_http.py` (`_headers`, `_graphql`).

## What it fetches

| Field | Source |
|---|---|
| `stars`, `forks`, `watchers`, `network_count`, `open_issues_count` | Counts from the requested repository |
| `followers`, `following`, `public_repos`, `public_gists` | Owner's public user profile |
| `orgs_count` | Organizations returned by the public user organizations request |
| `total_commits`, `contributions_last_year`, `contributions_calendar` | Owner's GraphQL contributions collection, calendar total and daily entries |
| `repos`, `languages` | Paginated repository records and language-byte totals across non-forks |

## CLI

```bash
uv run python -m scripts.fetch_metrics \
  --owner wyattowalsh \
  --repo wyattowalsh \
  --output /tmp/metrics.json
```

## Authentication

Set `GITHUB_TOKEN` for authenticated REST and GraphQL requests. Without it, the standalone collector can retrieve public REST data with lower rate limits. Supplemental card generation requires authentication.

## Output shape

```json
{
  "total_commits": 5000,
  "stars": 150,
  "contributions_last_year": 800,
  "followers": 200,
  "forks": 40,
  "network_count": 100,
  "open_issues_count": 7,
  "orgs_count": 2,
  "watchers": 20,
  "repos": [
    {"name": "example", "full_name": "owner/example", "fork": false, "stargazers_count": 50, "language": "Python"}
  ],
  "languages": {"Python": 125000},
  "contributions_calendar": [
    {"date": "2026-01-02", "count": 4, "color": "#216e39"}
  ],
  "collection_failures": []
}
```

## Caching

Each invocation collects fresh data. A failed or truncated repository traversal records `languages` in `collection_failures`. A malformed or failed calendar response records `contributions_calendar`. Either flag stops the supplemental publisher before it replaces the required cards.

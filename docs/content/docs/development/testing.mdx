## Stack

| Tool | Purpose |
|---|---|
| `pytest` | Test runner |
| `pytest-xdist` | Parallel test execution (`-n auto`) |
| `hypothesis` | Property-based / fuzz testing |
| `pytest-cov` | Coverage reporting |
| `pytest-mock` | Mock utilities |

## Run tests

```bash
# Full suite (parallel) via CLI
uv run readme dev test

# Direct test selection, without the CLI wrapper's isolated report bundle
uv run python -m pytest

# Single file, serial (useful for debugging)
uv run python -m pytest tests/test_cli.py -v -n 0

# Only non-integration tests
uv run python -m pytest -m "not integration" -v

# Filter by expression
uv run readme dev test -k "test_banner"

# Skip coverage
uv run readme dev test --no-coverage
```

## pytest configuration

From `pyproject.toml`:

```toml
[tool.pytest.ini_options]
addopts = "-n auto --verbose --hypothesis-show-statistics --cov=./scripts --cov-fail-under=95.0 ..."
testpaths = ["tests"]
timeout = 500
```

Coverage starts fresh for each authoritative CLI run. The CLI creates a unique
`logs/runs/<id>/` directory containing its coverage database and HTML report,
pytest HTML report, JUnit XML, and debug log. Use `--report-dir` to choose an
explicit isolated location. Coverage append is intentionally not a global
default. The checked-in 95.0% floor is accepted only after two locked,
unchanged-tree full-suite runs reproduce the same exact totals and source-file
membership. The accepted baseline is 96.15% across 77 source files,
leaving more than one percentage point of headroom above the enforced floor.

`uv run readme dev lint` also runs the structured `ty` ratchet. Its checked-in
baseline records exact warning counts by source path and rule: configured
errors, tool crashes, new pairs, or count increases fail, while warning
reductions pass without baseline churn.

The docs application has an independent assurance lane:

```bash
pnpm --dir docs install --frozen-lockfile
pnpm --dir docs test
pnpm --dir docs typecheck
pnpm --dir docs build
```

`typecheck` first runs the locked Fumadocs and Next type generators, producing
ignored `.source/` and `.next/types/` declarations before the non-incremental
TypeScript check. The docs workspace permits only `esbuild`'s required install
script. CI proves the sequence from a clean generated state in a separate
Node.js 24 job, so a docs regression cannot be hidden by a green Python job.

## Golden-file tests

`tests/test_ink_garden.py::TestGoldenFiles` compares deterministic SVG output against stored fixtures:

```
tests/fixtures/ink_garden/
├── minimal_full.svg   # 304,020 bytes
├── rich_full.svg      # 1,557,137 bytes
└── rich_mid.svg       # 1,503,670 bytes
```

To regenerate after an intentional output change:

```bash
# Delete fixtures and re-run to regenerate
rm -rf tests/fixtures/ink_garden/
uv run python -c "
from scripts.art.ink_garden import generate, seed_hash
import pathlib
# ... (see test file for full snippet)
"
uv run python -m pytest tests/test_ink_garden.py -v
```

## Mocking conventions

- Heavy rendering (repo-owned SVG helpers, Cairo) — patched via `@patch` at the source module
- Lazy imports — patch at `scripts.banner.generate_banner`, NOT `scripts.cli.generate_banner`
- Config I/O — use `tmp_path` fixture + real YAML files (no config mocking)
- Do **not** mock the database (N/A) or the filesystem with MagicMock (use `tmp_path`)

<Callout type="warn" title="Loguru handler reset">
`scripts/utils.py` calls `loguru_logger.remove()` at import time. Tests that import any `scripts.*` module need the `reset_loguru_handlers` autouse fixture (see `test_utils.py`).
</Callout>

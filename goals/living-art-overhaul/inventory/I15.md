### Why `--only` does not touch other styles

1. `_selected_living_art_styles("inkgarden")` returns `("inkgarden",)` (`_common.py:109-119`). Unknown keys exit 1.
2. `render_timelapse(..., styles=["inkgarden"])` loops **only** those keys (`timelapse.py:436`, `:482-535`). Unknown keys in the list are skipped (`:483-485`).
3. GIF write path is `out_dir / f"living-{style}.gif"` (`timelapse.py:532`). `_gif_output_transaction` locks **that** path only (`_gif_optimize.py:360-417`).
4. MP4 is `gif_path.with_suffix(".mp4")` (`timelapse.py:337`). Different styles → different files. Parallel `G1*` locks (`L-ASSET-IG` …) match this.
5. Partial CLI **skips** `sync_living_art_artifacts` / index refresh (`_common.py:210-216`; test `tests/test_cli.py:178-214`). Manifest/gallery stay as they were. **G2** is the fleet check, not G1.

Do **not** omit `--only`. Default `styles or ALL_STYLES` (`timelapse.py:436`) regenerates all six. `generate all` also calls full `living_art()` (`all_cmd.py:215-220`).

CLI completeness: returned GIF names must equal **requested** styles only (`_common.py:161-204`). A `--only inkgarden` run in a dir that also has stale `living-topo.gif` is fine — those other files are not in `outputs`. Writing into `.github/assets/img` in place with `--only` replaces one pair and leaves the other five.

Docs mismatch (I16 owns copy): `living-art-modes.mdx:100` says `--only` reports missing “other five” GIFs. Code does **not**. Isolated CI dirs contain one GIF and succeed (`profile-updater.yml:1100-1124` passes a 1-name `budgets={expected_name: budget}`).

## Pipeline (one style)

```text
metrics + history
  → validate_live_*_payload
  → build_daily_snapshots(..., include_today=True)   # full calendar spine (shared)
  → sample_frames(..., max_frames=120)
  → validate_snapshot_monotonic_contract(sampled)
  → seed_hash(final_snapshot.metrics_dict)           # one seed for all frames
  → _compute_frame_durations(n_sampled)              # ~30s, last frame 3000ms
  → for style in active_styles:                      # one if --only
        ProcessPoolExecutor: _render_single_frame
        _select_valid_frames_with_durations
        _assemble_gif → living-{style}.gif
        _export_mp4   → living-{style}.mp4   # does not fail the GIF
```

Evidence: `timelapse.py:389-542`.

Spine is built **once per `render_timelapse` call**, even with `--only`. Isolation is write-set, not snapshot cost. Timeout is 1200s for the **whole** call (`timelapse.py:399`, `:487-492`); `--only` gets the full budget. CI job timeout is 45 minutes (`profile-updater.yml:1049`).

### GIF assembly + optimize contract

`_assemble_gif` (`timelapse.py:219-328`):

- Private stage via `_gif_output_transaction`; public path changes once after validation (`_gif_optimize.py:360-417`).
- Quantize 192 colors, loop=0, Pillow `duration=durations`.
- If stage `> max_size_mb` (default **12.0 MB**): re-quantize 128 colors; if still over, **halve resolution** (`timelapse.py:295-324`). Halving 400×400 → 200×200 **fails** `LIVING_ART_CANONICAL_DIMENSIONS` (`artifacts.py:39`, `:193-198`). GEN must stay under 12 MB **and** the stricter per-style budget (lenia 1.2 MB). Assembly does not know per-style budgets.
- Then `_optimize_gif_with_gifsicle` on the **stage** only (`timelapse.py:326`; `_gif_optimize.py:496-508`). Replace only if smaller **and** `_preserves_playback_contract`: same dimensions, frame count, per-frame durations, loop, every composited RGBA frame (`_gif_optimize.py:467-478`). Missing gifsicle / failed / larger / contract change → keep source.

`scripts/art/AGENTS.md:61-70` is the human copy of that GIF contract.

### `_export_mp4`

```331:381:scripts/art/timelapse.py
def _export_mp4(gif_path: Path) -> Path | None:
    """Write a sibling H.264 MP4 when ``ffmpeg`` is on PATH.

    Uses yuv420p, ``+faststart``, and CRF 23. Missing ffmpeg or encoder
    failures are logged and skipped so the GIF contract is unchanged.
    """
    mp4_path = gif_path.with_suffix(".mp4")
    command = [
        "ffmpeg", "-y", "-hide_banner", "-loglevel", "error",
        "-i", str(gif_path),
        "-an", "-c:v", "libx264", "-pix_fmt", "yuv420p", "-crf", "23",
        "-vf", "scale=trunc(iw/2)*2:trunc(ih/2)*2",
        "-movflags", "+faststart", str(mp4_path),
    ]
```

| `-y` in-place overwrite, **no** flock/transaction | `339-357` | One writer per style (locks already); do not dual-run the same `--only` |
| Even-dimension scale | `354` | 400 is even → 400×400 H.264 |
| Timeout 180s; missing ffmpeg / nonzero / empty → unlink, return `None` | `360-379` | GIF still “success”; **check the mp4 yourself** |
| Not in `render_timelapse` return list | `533-535`, `:401-428` | CLI prints GIFs only (`_common.py:206-208`) |
| **No tests** name `_export_mp4` / ffmpeg | `tests/` rg empty | G1 is the first hard MP4 gate |

CI: matrix upload lists gif+mp4 (`profile-updater.yml:1132-1138`) but `if-no-files-found: error` succeeds if **any** listed path exists — GIF-only would still upload. `validate_living_art_byte_budgets` (`artifacts.py:159-288`) on each canonical GIF:

- name ∈ budgets; bytes ≤ budget; total ≤ total budget
- width/height == 400×400
- loop == 0
- frames in **2..120** (not “exactly 120”)
- `duration_ms >= 24000`; `durations_ms` all positive ints; `sum(durations_ms) == duration_ms`; `len(durations_ms) == frames`

Tests: `tests/test_living_art_media.py:363-388` (wrong size / 1 frame / 23990 ms / 121 frames); `tests/test_timelapse_runtime_contract.py:16-24` (120-frame plan ≥24s, ≤32s, last hold 3000ms); `tests/test_daily_snapshots_fidelity.py:622-625` (sample default == 120); `tests/test_living_art_artifact_handoff.py:259` (workflow `max_frames` == 120).

Duration plan (`_compute_frame_durations`, `timelapse.py:116-189`): ~10% first frames at 260ms, middle at ≥160ms, ~20% late at 220ms, **final hold 3000ms**, then trim overrun toward 30s. Dropped frames keep their planned duration by index (`:192-211`) — a hole does not steal the next frame’s hold.

`sample_frames` (`daily_snapshots.py:1820-1954`): never more than `max_frames`; always first and last day when `max_frames >= 2`; chronological anchors + high-transition days + gap splits. One **sampled day** per frame, not necessarily adjacent days (`living-art-modes.mdx:49-53`).

CLI `--max-frames` has `min=5` (`art.py:240`). Direct `render_timelapse(max_frames=2)` is possible; published GEN must pass **120**.

## Frame *t* = cumulative end-of-day world

Fact (`facts.md`): “Frame t is the cumulative end-of-day world from account creation through that day.”

Clock:

1. `build_daily_snapshots` (`daily_snapshots.py:972-982`): one `DailySnapshot` per calendar day from `history["account_created"]` through `_timeline_end_day`. Published path sets `include_today=True` (`timelapse.py:441-446`; asserted `tests/test_timelapse_runtime_contract.py:62-97`). Today is the **terminal** snapshot, including a partial day (`daily_snapshots.py:796-802` documents the opposite default for stability; timelapse overrides it).
2. Each day’s `metrics_dict` carries `cumulative_state` (`daily_snapshots.py:1233+`), then `_build_render_state` (`:352-358`, attached `:1395-1400`) and `_build_evolution_state` (`:1404-1409`). Channels are monotone (`validate_snapshot_monotonic_contract`, `:1440+`; `MONOTONIC_CUMULATIVE_KEYS` `:36-52`).
3. `sample_frames` picks ≤120 of those days. `validate_snapshot_monotonic_contract(sampled)` again (`timelapse.py:457`).
4. Frame *t* is sampled snapshot *t*: `generate(snapshot.metrics_dict, seed=final_seed, maturity=snapshot.maturity, timeline=False)`.
5. Generators: `is_monotonic_timelapse_metrics` true when `render_state` or `cumulative_state` present (`shared/metrics.py:205-215`); `resolve_render_metrics` prefers `evolution_state` then `render_state` (`:182-202`). Four-channel encoding is `shared/accretion.py:1-6` (“Frame t is the cumulative end-of-day world through day t”).

Pretty motion that ignores this clock cannot win a bake-off slot (grill + facts). `animate.py` GIF mode interpolates **maturity only** on one current `target` (`animate.py:441-459`) — that is **not** frame *t*.

Shared-spine fact test: `tests/test_living_art_media.py:1643-1661` (`build_daily_snapshots` + `sample_frames` + monotonic check in `render_timelapse` source; committed `living-{style}.gif` have `n_frames > 1`).

`DailySnapshot` docstring still says “all 4 generators” (`daily_snapshots.py:107`) — stale; six styles consume it.

## GEN wave implications (do not open repo-growth)

1. **One pair per lock.** `G1ig`…`G1fe` may run in parallel if each uses `--only` and only writes its two files. Do not refresh the living-art index until G2 (CLI already skips).
2. **Same metrics/history for all six** so the sampled spine matches (CI: one prepare artifact).
3. **Hard args:** `--max-frames 120 --size 400`. Do not pass `--frames 6` / `--size 96` (those exist only in rehearsal tests).
4. **Stay inside current GIF budgets.** `_assemble_gif`’s 12 MB cap is **looser** than lenia/genetic/physarum/ferrofluid/inkgarden and only slightly above topo (10 MB). A redesign that inflates GIF bytes fails G2 / `validate_living_art_byte_budgets` — the fix is encoding/quantization, **not** raising `LIVING_ART_BYTE_BUDGETS` (out of scope: `openspec/changes/prevent-living-art-repo-growth`).
5. **Never trigger the 12 MB halve** — that breaks 400×400.
6. **Require ffmpeg** and assert sibling MP4 size > 0. CLI will not fail for you. No MP4 byte cap exists; do not add one.
7. **Do not use** `generate animated`, `generate all` without `--only`, or unscoped `generate living-art`.
8. **Dropped frames:** if rasterization fails, frame count and runtime can slip under the 24s / 2-frame floors. Treat a holey GIF as a failed G1, not a budget workaround.
9. **G3** can decode first/mid/last frames from the new GIFs (Pillow `n_frames`); it should not re-render.
10. After K2, `--only` keys remain **candidates**; default generate / CI matrix become **shipped**. Until then shipped == candidates == six. G1 still uses today’s six keys.

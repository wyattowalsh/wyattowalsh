## Module

`scripts/banner.py` — ~1900 lines. Uses `numpy` plus the repository-owned,
string-based `scripts.svg_drawing` compatibility API; `svgwrite` is not a
dependency.

`scripts/banner_patterns.py` — `PatternType` enum extracted for zero-dep import.

## Entry point

```python
from scripts.banner import BannerConfig, generate_banner

cfg = BannerConfig(
    title="Wyatt Walsh",
    subtitle="Software Engineer & AI Enthusiast",
    output_path=".github/assets/img/banner.svg",
    width=1200,
    height=630,
    optimize_with_svgo=True,
    dark_mode=False,
)
generate_banner(cfg=cfg)
```

`generate_banner` is called **twice** by the CLI: once for `dark_mode=False` (light), once for `dark_mode=True` (dark). The dark output path is derived automatically by inserting `-dark` before the extension.

Each generator call removes its exact prior target, validates a regular,
non-empty, well-formed SVG after rendering and again after optional SVGO, and
cleans partial output on failure. The CLI requires the fresh light/dark pair;
if either variant fails or is absent, the command exits nonzero and does not
report stale checked-out bytes as success.

| Field | Type | Default | Notes |
|---|---|---|---|
| `title` | `str` | `"Wyatt Walsh"` | Main heading |

## PatternType

Defined in `scripts/banner_patterns.py`. Live variants:

| Value | Description |
|---|---|
| `LORENZ` | Lorenz strange attractor |
| `NEURAL` | Neural-network node graph |
| `FLOW` | Perlin flow field |
| `MICRO` | Micro-geometry lattice |
| `AIZAWA` | Aizawa attractor |

The shared enum also exposes `CLIFFORD`, which is implemented by
`scripts/generative.py` rather than the banner pipeline.

<Callout type="info">
The banner pipeline renders all five banner pattern groups. Its deterministic
seed and configuration control their geometry.
</Callout>

## SVGO optimization

If `optimize_with_svgo=True` and `svgo` is on `PATH`, the generated SVG is piped
through SVGO to reduce file size and then validated again. The shared optimizer
logs a warning and retains the already-valid SVG when SVGO is unavailable or
fails; the updater installs its reviewed exact SVGO release so that production
generation does not take that fallback.

## Output files

| File | Description |
|---|---|
| `banner.svg` | Light-mode banner |
| `banner-dark.svg` | Dark-mode banner (auto-derived path) |

## Workflow file

`.github/workflows/profile-updater.yml`

**Triggers:** `push` to `main`/`master`/`dev`, daily at 01:00 UTC, `workflow_dispatch`.

Manual dispatch also exposes `metrics_probe_mode`, which runs only the probe lane for the fuller `lowlighter/metrics` surface (same pin as production; no Spotify on Action `with:`).

## Job graph

```text
probe-full-metrics (manual only)

update-starred-lists
        ▼
generate-assets
        ▼
generate-profile-metrics
        ▼
generate-event-art
        ▼
update-readme-wakatime
        ▼
update-skills
```

## Job details

### `update-starred-lists`

Uses the `starred` CLI to rebuild `.github/assets/topics.md` and `.github/assets/languages.md` from your GitHub stars.

```bash
uv run starred --username wyattowalsh --sort \
  --filename .github/assets/languages.md
uv run starred --username wyattowalsh --sort --topic --topic_limit 500 \
  --filename .github/assets/topics.md
```

Commits both files with `chore(data): update awesome-stars lists`.

### `generate-assets`

Depends on `update-starred-lists`. Generates:
- QR code — `generate qr`
- Word cloud by topic — `generate word-cloud --from-topics-md` → `wordcloud_typographic_by_topics.svg`
- Word cloud by language — `generate word-cloud --from-languages-md` → `wordcloud_typographic_by_languages.svg`

Commits to `.github/assets/img/`.

### `update-readme-wakatime`

Uses [`anmol098/waka-readme-stats`](https://github.com/anmol098/waka-readme-stats) to inject WakaTime coding stats. Requires `WAKATIME_API_KEY` secret.

### `generate-profile-metrics`

Uses [`lowlighter/metrics`](https://github.com/lowlighter/metrics) pinned to the `v3.34` release SHA `65836723097537a54cd8eb90f61839426b4266b6` for the stable GitHub-native cards. Plugins are split across three SVGs so README height stays manageable:

| Asset | Ownership | Plugins / contents |
|---|---|---|
| `metrics.svg` | lowlighter (primary) | `base` (header/activity/community/metadata), `isocalendar`, `languages*`, `notable`, `topics`, `traffic` (token-gated), `achievements` (compact), `calendar` (current year) |
| `metrics.additional.svg` | lowlighter (additional) | `repositories` (+ featured list aligned to `config.yaml`), `stargazers`/`stars` (token-gated), `people` |
| `metrics.extra.svg` | lowlighter (overflow) | `reactions`, `followup` |

**Kept OFF on every lowlighter step** (owned by supplemental cards or out of scope): `habits`, `activity`, `music`, `gists`, `tweets`. Every lowlighter `with:` sets `plugin_music: no`. **Never** pass Spotify credentials into lowlighter/`felipecrs` (or any metrics fork) via `with:`.

Repo-owned supplemental cards replace the upstream-brittle / third-party panels:

| Asset | Ownership | Source |
|---|---|---|
| `metrics-habits.svg` | first-party supplemental | GitHub-backed coding habits |
| `metrics-activity.svg` | first-party supplemental | GitHub-backed recent activity |
| `metrics-music.svg` | first-party supplemental | Spotify via step `env:` only (`scripts/supplemental_metrics.py`) |
| `metrics-posts.svg` | first-party supplemental | X OAuth1 via step `env:` only |

The intended steady state is the three-card `lowlighter` stack plus validated supplemental cards below it in the README.

The job hardens metrics updates with `scripts.metrics_svg`:
- backs up the previously committed metrics SVGs (`metrics.svg`, `metrics.additional.svg`, `metrics.extra.svg`) before regeneration
- validates each render and rejects known degraded payloads
- validates supplemental assets against a manifest of required markers
- restores the previous valid `lowlighter` asset if a new SVG is malformed, contains a known error payload, or matches the placeholder SVG
- commits only after all three stable cards plus all enabled supplemental cards pass validation

Placeholder metrics SVGs are treated as invalid recovery artifacts, not the desired output, and are never the intended steady state.

### `probe-full-metrics`

Manual diagnostics lane for the fuller `lowlighter/metrics` surface (same pin as production — **not** `felipecrs`). It exists to answer questions like:

- does the current `METRICS_TOKEN` satisfy the repositories block?
- do upstream `habits` / `activity` panels still render degraded payloads? (probe-only; production keeps them off)
- do promote-set plugins (`achievements`, `calendar`, `people`, `reactions`, `followup`) render cleanly?

Probe renders three SVGs (`metrics.probe.primary.svg`, `.additional.svg`, `.extra.svg`), always with `plugin_music: no` and **no** Spotify secrets in Action `with:` inputs. Spotify health belongs to the supplemental-metrics path only.

It uploads probe SVG artifacts and fails closed if the probe renders or validation fail.

### `generate-event-art`

Fetches live metrics + history via `scripts/fetch_metrics.py` and `scripts/fetch_history.py`, then runs `uv run python -m scripts.cli generate living-art` to refresh the canonical living-art timelapse surface.

The job stages and commits:

- `.github/assets/img/living-*.gif`
- `.github/assets/img/living-art-manifest.json`
- `.github/assets/img/living-art-preview.html`
- `docs/public/showcase/living-*.gif`
- `docs/public/showcase/living-art-manifest.json`
- `docs/public/showcase/living-art-preview.html`

The uploaded staging bundle also includes the fetched `metrics.json` and `history.json` inputs plus the mirrored docs showcase surface for review.

### `update-skills`

Depends on `update-readme-wakatime`. Runs:
- `generate readme-sections` — assembles all dynamic README sections
- `generate skills` — re-renders skills badges

Commits:

- `README.md`
- `.github/assets/img/readme/featured-card-*.svg`
- `.github/assets/img/readme/featured-projects.manifest.json`
- mirrored docs showcase assets under `docs/public/showcase/featured-projects/`
- `docs/public/showcase/featured-projects.manifest.json`

## Secrets used by the workflow

| Secret | Used by | Notes |
|---|---|---|
| `GITHUB_TOKEN` | All jobs | Auto-provided by Actions |
| `METRICS_TOKEN` | `generate-profile-metrics`, `probe-full-metrics` | Canonical repo: expected classic PAT for repo-aware metrics (`read:user`, `repo`, `read:org`, and optionally `gist`). Forks can omit it, but repository-aware sections will be reduced and recovery may preserve the last valid asset. |
| `WAKATIME_API_KEY` | `update-readme-wakatime` | Optional WakaTime API key; README WakaTime update is skipped when absent |
| `SPOTIFY_CLIENT_ID` | `generate-profile-metrics` (supplemental step `env:` only) | Optional for the repo-owned `metrics-music.svg` supplemental card — never passed to lowlighter `with:` |
| `SPOTIFY_CLIENT_SECRET` | `generate-profile-metrics` (supplemental step `env:` only) | Optional for the repo-owned `metrics-music.svg` supplemental card — never passed to lowlighter `with:` |
| `SPOTIFY_REFRESH_TOKEN` | `generate-profile-metrics` (supplemental step `env:` only) | Optional for the repo-owned `metrics-music.svg` supplemental card; mint it with `uv run readme auth spotify-refresh-token` and store it as a repo secret |
| `X_API_KEY` | `generate-profile-metrics`, `probe-full-metrics` | Optional X API key for the repo-owned `metrics-posts.svg` supplemental card via OAuth 1.0a user-context |
| `X_API_KEY_SECRET` | `generate-profile-metrics`, `probe-full-metrics` | Optional X API key secret for the repo-owned `metrics-posts.svg` supplemental card |
| `X_ACCESS_TOKEN` | `generate-profile-metrics`, `probe-full-metrics` | Optional X access token for the repo-owned `metrics-posts.svg` supplemental card |
| `X_ACCESS_TOKEN_SECRET` | `generate-profile-metrics`, `probe-full-metrics` | Optional X access token secret for the repo-owned `metrics-posts.svg` supplemental card |

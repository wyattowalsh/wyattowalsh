## Finding

GitHub **issues / PRs / discussions** play uploaded MP4/MOV/WEBM. GitHub **README HTML `<video>`** is still widely stripped in 2026. A different “native” path — drag-drop upload that stores the file on GitHub’s CDN and pastes a bare `user-images.githubusercontent.com` / `github.com/.../assets/...` URL — can render a player in some repo READMEs, but that is an **external host**, which this goal forbids.

Current Living Art is already the **fallback shape** (visible GIF poster, `href` to in-repo `.mp4`), frozen by GFM tests as the **only** legal form, at wrap `width="360"`, with **`<details>` forbidden**. Video is **not** primary today. Grill: do not treat that GIF-poster-linking-to-MP4 as the designed default — try `<video>` on `origin/dev`, then keep it **or** fall back. A stripped `<video>` with no inner GIF would blank the gallery (violates `fact-visible-art`). Fallback is an allowed done state, not a failed goal.

`video-check.md` does **not** exist yet. V1 writes the template.

### Sanitizer / GFM (why strip is the default)

| Source | URL | Claim |
|---|---|---|
| github/markup README | https://github.com/github/markup | After convert-to-HTML, GitHub.com **sanitizes aggressively** (`script`, inline styles, extra `iframe`s / `object`s, etc.). Only step 1 is the public gem; sanitization is on github.com. |
| html-pipeline `SanitizationFilter::DEFAULT_CONFIG` | https://github.com/gjtorikian/html-pipeline/blob/main/lib/html_pipeline/sanitization_filter.rb | **Elements do not include** `video`, `audio`, `iframe`, `embed`, `object`. **Do include** `img`, `a`, `p`, `picture`, `details`, `summary`, `source`. `source` attributes: **`srcset` only** (no `src`). `img`: `src`, `alt`, `loading`, `longdesc`. **Not** in the global attr list: `autoplay`, `muted`, `loop`, `playsinline`, `controls`, `poster`. GitHub.com may customize, but 2026 field reports match this allowlist. |
| GitHub Docs — collapsed sections | https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/organizing-information-with-collapsed-sections | `<details>` / `<summary>` are **supported** GFM. Per-piece legends (M2) are legal HTML; current tests forbid them anyway. |
| GitHub Docs — basic syntax | https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax | Images, HTML comments, some HTML. **No** README `<video>` API. |

**Autoplay is a second fail axis.** `fact-video-fallback`: strip **or** no autoplay → GIF+click. Even if `<video>` survived, browsers require `muted` (+ usually `playsinline`) for autoplay; those attributes are not in the public sanitizer list. V2 must record **play** vs **strip** vs **plays-but-no-autoplay**.

## Modules

- `scripts/starred_lists.py` — strict GitHub-star pagination plus deterministic, paired language/topic Markdown publication
- `scripts/word_clouds/generate.py` — orchestration, file I/O, CLI-facing settings, and output dispatch
- `scripts/word_clouds/metaheuristic.py` — animated SVG renderer that sequences 25 solver layouts into one asset

<Callout type="warn" title="Two config models">
`WordCloudSettingsModel` in `config.py` is the top-level YAML config (part of `ProjectConfig`). `WordCloudSettings` in `scripts/word_clouds/generate.py` is the strict runtime generator config with `extra="forbid"`. Extra keys silently pass in the first, raise `ValidationError` in the second.
</Callout>

## What it generates

SVG word clouds where:
- **Topics cloud** — keywords from repositories you've starred, sorted by topic frequency
- **Languages cloud** — programming languages across your starred repos

The README and CI pipeline use deterministic static `TypographicRenderer`
assets. The animated metaheuristic renderer remains available for manual
generation when solver-to-solver motion is desired.

## Optimization model

All metaheuristic frames solve the same placement problem. The objective is "lower is better" and combines:

- Hard feasibility penalties for overlap and out-of-bounds words
- Packing density inside the occupied hull
- Visual balance around the canvas center
- Whitespace uniformity between neighboring words
- Reading-flow penalties for hard-to-scan rotations
- Landscape-aspect bias so layouts stay broad instead of collapsing into portrait stacks
- Size-gradient preference so larger words stay closer to the visual center

The readability policy is active during solver sampling, not just final scoring. Large words can use a different rotation palette than smaller words, which lets you keep headline terms mostly horizontal while still allowing more variation in the tail.

## Input data

The word cloud reads Markdown produced by the repository-owned
`scripts.starred_lists` module:

```
.github/assets/topics.md    ← topic-grouped starred repos
.github/assets/languages.md ← language-grouped starred repos
```

The nightly `update-starred-lists` job traverses the starred-repository GraphQL
connection once and derives both views from that same validated snapshot. The
shared GitHub transport permits HTTPS requests only; private repositories are
excluded by default. Categories and entries are sorted deterministically, and
both files are staged before either destination is replaced.

Generate both inputs locally with the token in the environment, not in command
arguments:

```bash
export GITHUB_TOKEN="<token>"
uv run python -m scripts.starred_lists \
  --owner wyattowalsh \
  --languages-output .github/assets/languages.md \
  --topics-output .github/assets/topics.md \
  --topic-threshold 500
```

Malformed/truncated pagination, cursor/count drift, an unsafe repository URL,
or a partial publication fails nonzero without accepting a mismatched pair.
The workflow adds a consumer validation gate before either file reaches the
word-cloud job.

## CLI

```bash
# Topics word cloud
uv run python -m scripts.cli generate word-cloud \
  --config-path ./config.yaml \
  --from-topics-md \
  --output-path .github/assets/img/wordcloud_typographic_by_topics.svg

# Languages word cloud
uv run python -m scripts.cli generate word-cloud \
  --config-path ./config.yaml \
  --from-languages-md \
  --output-path .github/assets/img/wordcloud_typographic_by_languages.svg
```

When a source is explicitly requested, success requires the corresponding
output file to exist. Missing or empty Markdown, an empty parsed vocabulary, or
an absent renderer output exits nonzero instead of reporting a successful run
against a stale checked-out SVG.

## Configuration

Under `word_cloud_settings` in `config.yaml`:

```yaml
word_cloud_settings:
  output_dir: .github/assets/img
  output_filename: word_cloud.png
  max_words: 1000
  prompt: "My Tech Skills: Python, JavaScript, Cloud, AI, DevOps, SQL, React"
  stopwords: []         # Additional stopwords list
  layout_readability:
    standard_rotations: [0, 0, 0, -8, 8, 90]
    large_word_rotations: [0, 0, 0, -8, 8]
    large_word_threshold_ratio: 0.72
    reading_flow_weight: 2.0
    target_aspect_ratio: 1.8
    landscape_bias_weight: 1.4
```

Key knobs:

- `max_words` limits the generated vocabulary before rendering for both classic and SVG backends
- `stopwords` filters explicit prompt terms and markdown-derived frequencies before layout
- `standard_rotations` controls the general rotation palette
- `large_word_rotations` applies only to the largest words in the layout
- `large_word_threshold_ratio` decides which words count as "large"
- `reading_flow_weight` increases or relaxes the cost of difficult rotations
- `target_aspect_ratio` and `landscape_bias_weight` steer the solver toward wider layouts
- `prompt` is tokenized from comma/newline separated tags or free text when you generate directly from text

### Runtime SVG style controls

Programmatic `WordCloudSettings` and `override_settings_dict` calls additionally
support:

| Field | Default | Behavior |
|---|---|---|
| `palette_tokenization` | `coarse` | `none` keeps continuous interpolation, `coarse` uses up to eight colors, and `strong` uses up to four |
| `style_variant` | `default` | `topic` and `language` add stable semantic IDs to the SVG root |
| `custom_color_func_name` | — | Selects a registered color function; unknown names fail validation |
| `color_palette_override` | — | Uses one or more explicit `#RRGGBB` interpolation anchors |

These controls are runtime-only; they are not fields in the persisted YAML
model. They require an SVG-native renderer. The classic PNG renderer rejects
them instead of silently ignoring them. Per-call overrides are validated in a
temporary settings model and never mutate the generator's base settings.

## Output files

| File | Description |
|---|---|
| `wordcloud_typographic_by_topics.svg` | Static topics cloud preserving every parsed topic in a readable typographic layout |
| `wordcloud_typographic_by_languages.svg` | Static languages cloud preserving every parsed language in a readable typographic layout |

## Rendering backends

The `scripts/word_clouds/` subpackage provides several SVG renderers. The CI pipeline and README use the typographic renderer:

| Renderer | Strategy |
|---|---|
| `WordleRenderer` | Classic Wordle-style random placement |
| `ClusteredRenderer` | Grouped by semantic clusters |
| `TypographicRenderer` | Typography-focused layout |
| `ShapedRenderer` | Mask-based shape filling |
| `MetaheuristicAnimRenderer` | 25 solver frames ordered into one CSS-animated SVG |

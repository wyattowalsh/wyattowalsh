## Finding

Finalize’s living-art commit is **one message**, **two add mechanisms**.

1. **GIFs (required).** Magic pathspecs `:(glob).github/assets/img/living-*.gif` and `:(glob)docs/public/showcase/living-*.gif` plus four concrete manifest/gallery paths. Always passed to `commit_group` → `git add -A --`. Fail-closed: publish already required the canonical GIF inventory; an unmatched GIF glob would be a contract bug.
2. **MP4s (optional).** Separate bash glob `mp4s=(.github/assets/img/living-*.mp4)`, appended to `art_files` **only if** `mp4s[0]` exists. Tests **forbid** `:(glob).github/assets/img/living-*.mp4`. Comment: stage concrete paths so an empty glob cannot fail `git add`.
3. **Same `git add` invocation** only after that append. The GIF glob **never** matches `.mp4`. Video-primary / V4 click-through **must keep the `mp4s` block** (or an equally explicit MP4 path list). Unifying into `living-*.*` or one glob is a test failure and a design error.

The optionality is the whole lane, not just finalize: `_export_mp4` skips on missing ffmpeg; shard upload `if-no-files-found: error` succeeds if **the GIF** exists; assembler MP4 artifact `ignore`; finalize MP4 download `continue-on-error: true`; publish copies MP4s if the sibling dir exists. Inventory, byte budgets, and showcase sync are **GIF-only**.

Today the repo has all six img MP4s and **zero** showcase MP4s. README is GIF poster + `href` to img MP4 (`scripts/readme_sections.py:1132-1140`). That is the current V4-shaped fallback, not native `<video>`.

## A. Finalize commit machinery

Sole writer: job `finalize`, step **`Commit and push owned profile artifacts`** (`.github/workflows/profile-updater.yml:1534-1586`).

Helper (every owned group, including art):

```1545:1558:.github/workflows/profile-updater.yml
          commit_group() {
            local message="$1"
            shift
            local owned_files=("$@")
            if [ "${#owned_files[@]}" -eq 0 ]; then
              echo "Skipping empty group for: ${message}"
              return 0
            fi
            if [ -z "$(git status --porcelain --untracked-files=all -- "${owned_files[@]}")" ]; then
              echo "No changes for: ${message}"
              return 0
            fi
            git add -A -- "${owned_files[@]}"
            git commit -m "${message}"
          }
```

Porcelain **and** `git add` are scoped to `owned_files`. Paths not in that array are invisible: they cannot dirty the skip check and they are not staged. That is why appending MP4s is not cosmetic.

Art group (GIF pathspecs always; MP4s maybe):

```1572:1586:.github/workflows/profile-updater.yml
          art_files=(
            ':(glob).github/assets/img/living-*.gif'
            .github/assets/img/living-art-manifest.json
            .github/assets/img/living-art-preview.html
            ':(glob)docs/public/showcase/living-*.gif'
            docs/public/showcase/living-art-manifest.json
            docs/public/showcase/living-art-preview.html
          )
          # Optional MP4 siblings: only stage concrete paths that exist so
          # an empty glob cannot fail `git add`.
          mp4s=(.github/assets/img/living-*.mp4)
          if [ -e "${mp4s[0]}" ]; then
            art_files+=("${mp4s[@]}")
          fi
          commit_group "art: regenerate living-art assets" "${art_files[@]}"
```

README markup is a **different** group (`:1614-1618`, message `chore(readme): update dynamic sections and skills badges`). P0/V4 assembler edits land there. Media bytes land in the art commit. A README-only P0 does not exercise the `mp4s` block.

Loop guard: finalize `if:` skips when `head_commit.message == 'art: regenerate living-art assets'` (`:1266`, also listed at `:289` and siblings). P0/C2 must **not** use that message (or the other skip strings) or the next CI run no-ops.

Push remains `origin/dev` only (`:1625-1662`). I04 owns that lock; this leaf only notes that both GIF and MP4 bytes, if committed here, go to `dev`.

## B. Why GIF uses `:(glob)` and MP4 must not

| | GIF | MP4 |
|---|---|---|
| Pathspec kind | Git magic `:(glob)` quoted so bash does not expand | Bash glob into an array, then concrete paths |
| Surfaces | img **and** `docs/public/showcase` | img **only** |
| Always in `art_files`? | Yes | Only if `[ -e "${mp4s[0]}" ]` |
| Empty match | Would fail `git add` (fatal unmatched pathspec). Allowed because publish already required the GIF fleet. | Must **not** fail. `:(glob)…living-*.mp4` is therefore forbidden. |
| `git add -A` deletions | Yes — tracked `living-*.gif` removed from the worktree are staged (handoff rehearsal). | **No** — deleted MP4s are absent from the bash glob, so they are not in `owned_files`. |
| Leftovers still on disk | Publish unlinks extra `living-*.gif` not in budgets (`scripts/art/artifacts.py:1060-1066`); glob then stages those deletions. | Publish **never** unlinks `living-*.mp4`. Glob **re-adds** them (I03). |
| `nullglob` | N/A (git glob, not bash) | Finalize **forbids** `shopt -s nullglob` (`tests/test_profile_workflow.py:865`). Unmatched bash glob stays the literal `living-*.mp4`; `-e` is false; append skipped. That is the empty-safe substitute for nullglob. |

`:(glob)` is required for GIFs because `git add -- .github/assets/img/living-*.gif` would be bash-expanded (and with `set -euo pipefail` + no `nullglob` would pass a literal `*` path if empty). Quoting the magic pathspec lets **git** match tracked + worktree GIFs, including deletions.

Using the same `:(glob)` for MP4 would:

- Fail the art commit when ffmpeg skipped every style (today’s allowed state).
- Fail `tests/test_profile_workflow.py:478`.
- Accidentally start staging MP4 deletions (maybe desired at S13, but that is a **contract change**, not a cleanup).

S3 must not “simplify” to one glob. Plan (`goals/living-art-overhaul/plan.md:17`): *Video-primary must not assume one git add covers both.*

## E. What “one git add” would miss

Assume a well-meaning S3 change: drop `mp4s=` and rely on `art_files` GIF glob / `git add -A` of `.github/assets/img`.

| Event | With today’s split | GIF-glob-only (illegal) |
|---|---|---|
| New/changed `living-*.gif` | Staged | Staged |
| New/changed `living-*.mp4` | Staged **iff** append runs | **Not staged** — porcelain never looks at them; art commit may skip if GIFs are byte-identical |
| Deleted extra `living-*.gif` | Staged (glob + `-A`) | Staged |
| Deleted extra `living-*.mp4` | **Not staged** | Still not staged unless the whole img dir is added (out of contract) |
| Untracked leftover `living-retired.mp4` | Re-staged (I03) | Left untracked (better for S13, but then V4 href 404s if README still links it) |
| Showcase `living-*.gif` | Staged | Staged |
| Showcase `living-*.mp4` | N/A (none; no pathspec) | N/A |

Video-primary failure mode: GEN writes new MP4s, GIFs happen to match the previous commit (or only MP4s change). Without `mp4s+=`, `commit_group` prints `No changes for: art: regenerate living-art assets` and **github.com `<video>` / click-through keeps yesterday’s film**.

A second failure: MP4 download `continue-on-error` fires, `mp4_dir` missing, copy loop skipped, checkout still has **old** tracked MP4s. GIF glob commits new GIFs. Click/video points at **stale** MP4. Optional-MP4 was acceptable when GIF was the poster. It is not acceptable if MP4 is the primary README media unless V4/P0/C2 treat “stale film” as a failed check.

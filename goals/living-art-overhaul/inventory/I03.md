### `_validate_canonical_inventory` modes

Evidence: `artifacts.py:308-343`.

| `exact_directory` | Compared entries | Used by |
|---|---|---|
| `True` | **every** directory entry | Stage candidate + persisted stage (`stage_living_art_fleet`); downloaded stage (`publish_living_art_fleet`) |
| `False` | only `living-*.gif` | Producer source; `sync_living_art_artifacts` / persisted surfaces |

Both modes: expected names must be present; extras in the compared set fail; each expected path must be a regular non-symlink file. Symlinked directories fail earlier in `_require_real_directory` (`296-305`).

Implications:

- Stage dir may contain **only** the canonical GIFs (no MP4, no manifest, no gallery, no `banner.svg`).
- Primary img dir may contain MP4s, growth leftovers, metrics SVGs, etc., **as long as** the `living-*.gif` set equals the budget keys.
- A leftover **retired** `living-foo.gif` after S2 fails `exact_directory=False` even if MP4s and growth files are fine.
- Legacy `*-growth.gif` / `*-growth-animated.svg` are **not** `living-*.gif` → allowed on the primary surface. Confirmed by `test_fact_living_art_exact_six_excludes_legacy_growth_collateral` (`tests/test_living_art_media.py:1664-1673`).

### Filename regex / dark variants

`_TIMELAPSE_RE` (`artifacts.py:64-65`) is compiled at import from `LIVING_ART_STYLE_LABELS` keys:

```text
^living-(inkgarden|topo|genetic|physarum|lenia|ferrofluid)(-dark)?\.gif$
```

- Known style + optional `-dark` → descriptor (`_asset_descriptor`, `98-118`). Variant `"dark"` if suffix is `-dark`, else `"default"`.
- `living-*.gif` that does **not** match → `build_living_art_manifest` raises `Unsupported living-art GIF` (`132-133`).
- Matched `-dark` files are **not** in `LIVING_ART_BYTE_BUDGETS` → `unexpected canonical asset` in `validate_living_art_byte_budgets`. Test: `test_living_art_manifest_rejects_unbudgeted_gifs` (`living-topo-dark.gif`, `living-junk.gif`) at `test_living_art_media.py:435-450`.

No dual light/dark GIF pairs exist on disk. Matches fact-one-look.

If S2 drops a style from `LIVING_ART_STYLE_LABELS`, its leftover GIF stops matching the regex → **Unsupported** in `build_living_art_manifest`, and **unexpected** in inventory. Two rejection layers.

## Stage vs publish vs docs-showcase sync

```text
generate-event-art (per style)
  isolated dir → living-{style}.gif [+ optional .mp4]
  validate_living_art_byte_budgets({that gif: its cap}, total=that cap)

assemble-event-art  (read-only)
  merge shards → parts/
  stage_living_art_fleet(parts, stage)     # GIF-only, exact_directory=True
  copy living-*.mp4 into sibling living-art-mp4/   # NOT passed to stage
  upload living-art-stage-*  and  living-art-mp4-*

finalize
  publish_living_art_fleet(stage, .github/assets/img, docs/public/showcase)
  copy MP4 siblings onto img/              # unmanaged; no inventory
  re-validate GIF budgets + primary/public GIF hashes
```

### `stage_living_art_fleet` (`931-990`)

1. Validate **source** with `exact_directory=False` (full media+budget contract). Source may hold collateral.
2. Reject overlapping / non-empty / symlink stage.
3. Copy **only** `_canonical_living_art_names()` into a private candidate dir.
4. Validate candidate with `exact_directory=True`.
5. Atomic `os.replace` candidate → stage.
6. Re-validate persisted stage (`exact_directory=True`) and stable-manifest match vs source.
7. Returns the **source** manifest object (not written into the stage).

Stage is **media-only GIFs**. Manifest/gallery are never transferred. Matches AGENTS.md: “Never transfer manifests or galleries between jobs as an independent authority.”

Workflow assembler (`profile-updater.yml:1180-1197`) keeps that GIF-only stage and copies MP4s to a **sibling** dir. `if-no-files-found: ignore` on the MP4 upload (`1227-1234`).

### `sync_living_art_artifacts` (`886-928`)

Local/CLI index writer. Validates primary (`exact_directory=False`), writes manifest+gallery atomically, optionally mirrors to `public_surface_dir`.

CLI (`_common.py:74-84`, `210-216`): refresh only when the invocation’s style tuple equals **full** `LIVING_ART_STYLE_KEYS`. Partial `--only` skips refresh so an incomplete fleet cannot publish a truncated index.

Default public dir: `DEFAULT_PUBLIC_SURFACE_DIR = Path("docs/public/showcase")` (`26`). CLI uses it only if `docs/public` exists (`77-79`).

### `_sync_public_surface` (`823-883`)

1. Stage GIF copies + regenerated public manifest/gallery in a temp sibling.
2. Stable-payload match vs primary (ignores `generated_at`, `output_dir`).
3. Unlink existing managed names on the public dir: `living-*.gif`, `living-art-manifest.json`, `living-art-preview.html`.
4. `os.replace` staged files in.
5. Does **not** touch featured-project cards, wordclouds, or other showcase files.

This goal **does not redesign** `living-art-preview.html` as a second gallery (facts/grill). Publish will still regenerate it as a GIF grid from the shipped fleet. That is contract parity, not a gallery redesign.

### `publish_living_art_fleet` (`993-1092`)

Treats the downloaded stage as **untrusted**:

1. Validate stage `exact_directory=True` (inventory + budgets + animation).
2. Reject stage/primary/public path overlap; validate destination shapes.
3. Isolated candidate: copy canonical GIFs → `sync_living_art_artifacts` (regenerates both surfaces in temp).
4. Snapshot managed files on **both** live destinations (`_snapshot_managed_surface`).
5. **Mutation:** unlink primary `living-*.gif` **not** in `LIVING_ART_BYTE_BUDGETS` (`1060-1066`); atomic-copy shipped GIFs; `sync_living_art_artifacts` onto live primary+public.
6. On mutation failure: rollback both managed surfaces; unmanaged files (MP4s, growth, featured cards) stay.

Publish’s extra-GIF unlink is the GIF half of S13 **at CI finalize time**. It does **not** delete leftover MP4s. Local `sync_living_art_artifacts` does **not** unlink extras — leftover retired GIFs fail inventory before any write.

### Dual-surface postconditions

`_validate_persisted_surface_pair` (`797-820`): persisted manifest == generated object; gallery bytes == `_render_gallery`; recomputed inventory matches stable payload; primary vs public galleries identical; GIF hashes compared again in the workflow (`profile-updater.yml:1501-1505`).

Run-specific fields dropped for comparison: `generated_at`, `output_dir` (`44`, `346-352`).
